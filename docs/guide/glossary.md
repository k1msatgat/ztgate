# 용어

ztgate 의 화면과 안내서에 나오는 말을 모았습니다.

| 용어 | 뜻 |
|---|---|
| 기기 | 서버에 등록된 PC 나 커넥터 장비 하나. 기기 ID 와 기기 공개키로 서버의 기기 목록(`devices.conf`)에 한 줄로 있습니다 |
| 등록 코드 | 관리자가 기기 하나를 들이려고 만드는 일회용 코드(`XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`). 한 번 쓰면 사라지고, 기본 15분이 지나면 쓸 수 없습니다 |
| 초대 링크 | 서버 이름, 포트, 등록 코드를 묶은 링크(`ztgate://enroll?...`). Windows 에서 누르면 채워진 등록 창이 열립니다. `server.env` 에 `PUBLIC_ADDRESS` 가 있을 때 코드와 함께 나옵니다 |
| 서버 키 | 서버의 비밀 키(`/etc/ztgate/server.key`). 서버가 지키는 비밀은 이것 하나입니다. 잃거나 바꾸면 모든 기기가 다시 등록해야 합니다 |
| 기기 키 | 기기와 서버가 각자 같은 값으로 계산하는 키. 어디로도 오가지 않고, 연결할 때 기기가 자기임을 증명하는 데 씁니다 |
| 세션 | 연결 하나. 연결할 때마다 새 세션 키를 만들고, 세션 키는 기본 한 시간(`SESSION_LIFETIME`)마다 바뀝니다 |
| 포스처 | 그 순간의 PC 보안 상태. Windows 는 방화벽, 백신의 실시간 보호, BitLocker 를 보고합니다. 연결된 동안 10초마다 다시 보고합니다 |
| 접속 조건 | 기기마다 정하는 포스처의 최소 요건(`firewall=on` 같은 조건). 못 미치면 그 기기는 터널에 들어오지 못합니다 |
| ACL | 기기가 닿을 수 있는 목적지를 적은 규칙 목록(`acl.conf`). 위에서부터 처음 맞는 규칙을 따르고, 맞는 규칙이 없으면 거부합니다 |
| 태그 | 기기의 역할을 나타내는 이름(`tag=eng`). ACL 규칙이 태그로 기기를 고릅니다 |
| 사용자 로그인 | 회사 IdP(OIDC)로 그 기기를 쓰는 사람을 확인하는 것. ACL 의 `user=` 와 `group=` 규칙이 로그인한 사람에게만 열립니다 |
| 앱 커넥터 | 사내망 안에 두는 Linux 장비. 서버로 나가는 세션을 열어, 사내망에 들어오는 포트 없이 사내망을 내어 줍니다 |
| 주 서버, 부 서버 | 서버를 두 대 둘 때의 역할. 설정은 주 서버에서만 고치고, `ztgate-sync` 가 부 서버로 보냅니다 |
| 감사 로그 | 세션, 거절, 접근 판정, 관리 작업을 사건마다 JSON 한 줄로 적은 기록(`/var/log/ztgate/audit.log`). 12주 동안 둡니다 |
| 다시 읽기, 다시 시작 | `systemctl reload ztgate` 는 연결을 끊지 않고 기기 목록과 ACL 을 다시 읽습니다. `systemctl restart ztgate` 는 서버를 다시 띄우고, PC 는 바로 다시 붙습니다 |
| 늘 연결 (`AlwaysOn`) | Windows 정책. PC 가 켜지면 붙고, 사용자는 끊을 수 없습니다 |
| 끊긴 동안 차단 (`BlockWhenDown`) | Windows 정책. 터널이 열려 있지 않은 동안 사내 대역으로 나가는 연결을 막습니다. 서버 주소는 늘 허용합니다 |
| MCP | AI 에이전트가 서버를 다루는 통로. 셸 대신 정해진 도구(상태 보기, 등록 코드, ACL, 배포)만 엽니다 |
