# ztgate 운영 참고

서버를 운영할 때 찾아보는 사실을 모았습니다. 설치하고 기기를 들이는 순서는 [ztgate 서버 운영하기](admin.md)에 있습니다.

## 서버 요건

| 항목 | 요건 |
|---|---|
| 운영체제 | Ubuntu 22.04, Ubuntu 24.04, Rocky Linux 9, RHEL 9 (x86_64) |
| 주소 | 공인 주소, 또는 공인 주소에서 오는 포트 포워딩 |
| 포트 | UDP 9000 (`PORT`). UDP 를 막는 네트워크의 PC 를 받으려면 같은 번호의 TCP 포트도 (`TCP_PORT=9000`). Windows 는 같은 번호의 TCP 로만 넘어갑니다 |
| 이름 | DNS 이름을 권장합니다 (`vpn.example.com`). PC 는 연결할 때마다 이름을 다시 풀기 때문에, 서버 주소가 바뀌어도 PC 를 다시 설정하지 않습니다 |
| 함께 쓰는 프로그램 | Node.js 18 이상은 관리 도구 `ztgate_ctl` 에 필요합니다 (Ubuntu 22.04 의 기본 `nodejs` 는 12 라 따로 깝니다). nftables 는 서버 뒤로 내보낼 때, rsync 는 서버 두 대를 맞출 때 필요합니다 |

## 매일 쓰는 명령

| 보는 것 | 명령 |
|---|---|
| 지금 붙어 있는 PC 와 그 상태 | `sudo ztgate status` |
| 누가 언제 무엇을 했는지 | `sudo ztgate audit` (`/var/log/ztgate/audit.log`, 12주 보관) |
| 서버 로그 | `journalctl -u ztgate` |
| Prometheus 지표 | `sudo systemctl enable --now ztgate-exporter` 를 실행한 뒤 `127.0.0.1:9469/metrics` |

웹 콘솔의 개요와 감사 로그 화면도 같은 내용을 보여 줍니다.

## 문제 해결

| 증상 | 원인과 확인할 것 |
|---|---|
| PC 에 "서버가 답하지 않습니다"가 나온다 | 서버가 꺼져 있거나 UDP 포트가 막혔습니다. `systemctl status ztgate` 로 서버를 보고, 서버와 클라우드 방화벽의 UDP 포트를 봅니다. UDP 를 막는 네트워크라면 `TCP_PORT` 를 켭니다 |
| PC 에 "서버에 이 기기가 없습니다"가 나온다 | 기기 목록에 그 기기가 없습니다. 지운 기기라면 새 코드로 다시 등록합니다 |
| PC 에 "회사 보안 정책에 맞지 않습니다"가 나온다 | PC 상태가 그 기기의 조건에 못 미칩니다. 감사 로그의 `auth_denied` 에 사유가 있습니다 |
| 연결은 되는데 어떤 목적지에만 닿지 않는다 | 그 목적지를 허용하는 ACL 규칙이 없거나, 규칙의 태그, 사용자, 포스처 조건이 맞지 않습니다. 감사 로그의 `access` 줄에 판정이 있습니다 |
| PC 에 "서버가 이 프로그램보다 새 버전입니다"가 나온다 | PC 의 버전이 낮습니다. PC 를 올립니다 |
| 초대 링크가 나오지 않는다 | `server.env` 에 `PUBLIC_ADDRESS` 가 없습니다 |
| 부 서버에서 설정을 고칠 수 없다 | 정상입니다. 설정은 주 서버에서 고칩니다 |

## 지금 할 수 없는 것

- 기기를 다시 등록하지 않고 서버 키를 바꿀 수 없습니다. 그 방법은 설계 중입니다 ([ADR 0013](../decisions/0013-server-key-rotation.md)). 서버 키가 샜다고 의심되면 새 키를 만들고 모든 기기를 다시 등록합니다.
- 서버끼리 세션을 넘겨주지 않습니다. 다른 서버로 넘어간 PC 는 새로 연결하고, 넘어가는 몇 초 동안의 패킷을 잃습니다.
- macOS, iOS, Android 클라이언트가 없습니다.
