# 0001. 서버는 유저 공간에서 epoll 과 tun 으로 돈다

- 상태: 채택
- 날짜: 2026-09-20 (첫 서버 `e30a872`)

## 맥락

서버는 클라이언트의 UDP 패킷을 풀어 터널 안의 IPv4 패킷을 내부망으로 내보내고, 돌아오는 패킷을 다시 감싸 보내야 한다. 그 사이에 기기 인증, 포스처 판정, ACL, 감사 로그가 패킷마다 끼어든다. 이 판정들은 자주 바뀌고(정책, 사용자 토큰), 시험하기 쉬워야 한다.

## 결정

유저 공간 프로세스 하나가 UDP 소켓과 tun 장치를 epoll 하나에 걸고, 패킷마다 `recvfrom` → 열기 → 판정 → `write(tun)` 을 한다 (반대 방향은 `read(tun)` → 감싸기 → `sendto`). 세션 만료와 정책 다시 읽기는 같은 루프가 1초마다 깨어 처리한다. 나중에 워커 여럿으로 나눴지만(0005) 워커마다 같은 루프다.

## 검토한 다른 길

- **커널의 IPsec (XFRM) + IKE 데몬** — 데이터 경로가 커널이라 빠르지만, 패킷마다의 판정(포스처, 사용자, 기기 태그)을 넣을 자리가 XFRM 정책과 nftables 뿐이다. 세션마다 바뀌는 포스처를 패킷 판정에 쓰려면 결국 유저 공간과 오가야 한다.
- **커널 모듈** — 가장 빠르지만 한 번의 실수가 커널을 멈추고, 판정 로직을 바꿀 때마다 모듈을 다시 올려야 한다. 시험(`auth_check`)을 유저 공간에서 돌릴 수 없다.
- **WireGuard 위에 판정 프로세스** — 암호는 검증된 것이지만, 기기 ID 와 포스처를 핸드셰이크에 실을 수 없고(0002) 패킷마다의 사용자 판정은 다시 별도 경로가 된다.

## 결과

- 판정 로직은 평범한 C 코드라 고치고 시험하기 쉽다. `auth_check` 는 서버를 그대로 띄워 패킷을 직접 만들어 보낸다.
- 패킷마다 시스템 호출 두 번과 커널 ↔ 유저 복사가 있다. 측정은 README 의 "성능" 절에 있고, 워커를 늘려 나눠 받는다 (0005). 세션 하나의 속도는 워커 수와 상관없다.
- `CAP_NET_ADMIN` 만 있으면 되고, 서비스 유닛이 나머지 권한을 뗀다.
