# 0004. 등록하는 기기는 공개키만 올리고, 기기 키는 고정 키의 ECDH 로 뽑는다

- 상태: 채택
- 날짜: 2026-10-24 (`0c821cd` 서버 키와 공개키 기기). 등록 코드 자체는 2026-10-13 (`54bd0a1`)

## 맥락

처음에는 기기마다 256bit 대칭 키를 관리자가 만들어 기기와 서버의 목록에 손으로 넣었다. 키를 옮기는 길이 새는 길이고, 서버의 기기 목록이 새면 모든 기기로 가장할 수 있다. 등록 코드로 기기가 스스로 올라오게 한 뒤에도(v8 전) 기기 키가 등록 메시지에 실려 갔다.

## 결정

- 서버는 고정 키 쌍(`server.key`, `-k`)을 가진다. 등록하는 기기는 자기 고정 키 쌍을 만들어 공개키만 올리고, 서버는 기기 목록에 `p256:<공개키>` 로 적는다.
- 기기 키 = 서버 고정 키와 기기 고정 키의 ECDH 에서 뽑은 값. 양쪽이 따로 뽑으므로 어디로도 오가지 않는다. 핸드셰이크(0002)는 이 기기 키를 지금처럼 쓴다.
- 등록 답에 서버 공개키가 실리고, 기기는 그것을 고정해 다음부터 다른 공개키를 내미는 `CHALLENGE` 에 답하지 않는다.
- Windows 는 TPM 이 있으면 기기의 고정 비밀키를 TPM 안에 두고 연결할 때마다 TPM 으로 기기 키를 뽑는다.

## 검토한 다른 길

- **서명(ECDSA)으로 인증** — 서버가 뚫려도 기기로 가장할 수 없다. 핸드셰이크를 서명 중심으로 다시 짜야 하고, 기존의 대칭 기기 키 경로(손으로 올린 기기)와 두 길이 된다.
- **대칭 키를 그대로 두고 목록만 암호화** — 서버가 키를 풀어 써야 하므로 서버가 뚫리면 같다.

## 결과

- 기기 목록이 새도 공개키 기기의 키는 나오지 않는다. 서버의 비밀은 `server.key` 하나다.
- **`server.key` 를 가진 쪽은 모든 공개키 기기의 키를 뽑을 수 있다** (Noise KK 와 같은 성질). 서버 키를 바꾸면 그 기기들은 다시 등록해야 한다.
- 손으로 올린 공유 키 기기는 지금처럼 목록에 키가 있고, `CHALLENGE` 의 공개키를 고정하지 못한다.
