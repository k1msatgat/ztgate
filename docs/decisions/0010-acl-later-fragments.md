# 0010. ACL 은 IP 뒷조각을 포트 없이 판정한다

- 상태: 채택
- 날짜: 2026-10-25 (`31842be`)

## 맥락

ACL 은 `src / dst / proto / dport` 로 판정하고 상태를 추적하지 않는다. 조각난 TCP / UDP 의 두 번째 조각부터(fragment offset ≠ 0)는 L4 헤더가 없는데, 그 자리의 데이터를 포트로 읽어 판정이 데이터에 따라 달라졌다 — 허용한 포트로 가는 조각난 UDP 가 들쭉날쭉 끊겼다.

## 결정

Cisco ACL 의 non-initial fragment 처리를 따른다. 뒷조각은:

- 포트를 적은 `deny` 줄은 건너뛴다.
- `allow` 줄은 주소와 프로토콜로 맞춘다 (포트 조건을 보지 않는다).
- 포스처와 사용자 조건은 그대로 본다.

첫 조각은 지금처럼 포트로 판정한다. 감사 로그도 뒷조각에 포트를 적지 않는다.

## 검토한 다른 길

- **첫 조각의 판정을 기억했다가 뒷조각에 쓰기** — (출발지, 목적지, 프로토콜, IP ID) 표가 필요하다. 가장 정확하지만 표, 만료, 크기 상한이 더해지고, 뒷조각이 먼저 오면 버려진다.
- **서버가 조각을 합친 뒤 판정** — 메모리를 받는 쪽이 정하게 되어 조각 폭주에 약하고, 다시 쪼개 보내야 한다.
- **뒷조각을 모두 버리기** — 단순하지만 조각난 패킷이 아예 지나가지 못한다.

## 결과

- 첫 조각이 막힌 패킷은 목적지에서 합쳐지지 않으므로 뒷조각만으로는 아무것도 전달되지 않는다. 겹치는 조각으로 첫 조각의 포트를 덮어쓰는 것은 Linux 가 합칠 때 버린다.
- 포트를 막은 목적지로 가는 뒷조각이 목적지까지 가서 합쳐지지 못한 채 버려질 수 있다 (목적지의 조각 메모리를 잠깐 쓴다).
- `auth_check` 의 조각 시험 5개 (고치기 전에는 뒷조각 둘이 실패).
