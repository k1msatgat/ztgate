# 0005. 워커 여럿은 세션 표 하나를 읽기 / 쓰기 잠금으로 나눠 쓴다

- 상태: 채택
- 날짜: 2026-10-24 (`3b151fa`). 2026-10-25 에 `AUTH` 의 앞부분을 잠금 밖으로 옮겼다 (`ab1472e`)

## 맥락

스레드 하나(0001)로는 코어 하나만 쓴다. 세션이 여럿이면 코어를 나눠 써야 하지만, 세션 표, 기기 목록, ACL 은 핸드셰이크 / keepalive / 다시 읽기가 바꾸고 데이터 패킷은 읽기만 한다.

## 결정

- `-w N` 이면 워커 N 개가 저마다 UDP 소켓(`SO_REUSEPORT`, 같은 포트)과 tun 큐(`IFF_MULTI_QUEUE`)를 가진다. 커널이 출발지 주소로 소켓을 골라, 한 세션의 패킷은 늘 한 워커로 간다.
- 데이터 패킷은 표의 읽기 잠금 아래에서, 표를 바꾸는 일(핸드셰이크, keepalive, 로그인, 등록, 다시 읽기)은 쓰기 잠금 아래에서 한다. 세션 하나의 카운터 / 재전송 창은 세션 잠금으로 지킨다.
- 표를 보지 않는 비싼 일은 잠금 밖에서 한다: `AUTH` 의 nonce 확인과 기기 ID 를 푸는 ECDH (`auth_precheck`).

## 검토한 다른 길

- **워커마다 표를 나누기 (shared-nothing)** — 잠금이 없지만, 세션이 다른 워커로 옮겨 가는 경우(NAT 뒤에서 포트가 바뀜, TCP 로 바꿔 붙음)와 커넥터 중계(다른 세션으로 보내기)에서 워커끼리 넘겨야 한다.
- **RCU** — 읽기가 더 싸지만 다시 읽기와 세션 내리기의 수명 관리가 복잡해진다.

## 결과

- 워커 1 → 2 에서 세션 넷의 처리량이 1.66배 (README "성능").
- 쓰기 잠금 동안은 모든 워커의 데이터가 잠깐 멈춘다. 그래서 쓰기 잠금 안에 비싼 계산을 두지 않는다 — 처음에는 `AUTH` 의 ECDH 가 안에 있어, nonce 하나를 받아 둔 상대가 엉터리 `AUTH` 를 쏟아부으면 데이터 경로가 멈췄다 (2026-10-25 고침).
- 세션 하나의 속도는 워커 수와 상관없다.
