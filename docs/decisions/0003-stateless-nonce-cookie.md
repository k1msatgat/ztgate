# 0003. nonce 는 서버가 기억하지 않는 쿠키로 한다

- 상태: 채택
- 날짜: 2026-10-24 (프로토콜 v9 `7cca575`)

## 맥락

v8 까지는 `REQ` 가 기기 ID 를 밝히고, 서버가 그 기기에 내준 nonce 를 기억했다. 그러면 출발지를 위조한 `REQ` 로 서버의 표를 채우거나, 남의 기기 ID 로 `REQ` 를 보내 진짜 기기의 nonce 를 덮어쓸 수 있다. 또 `REQ` 에 기기 ID 가 보이면 엿보는 쪽이 어느 기기가 언제 붙는지 안다.

## 결정

nonce = 발급 시각(8바이트, `CLOCK_MONOTONIC` µs) | HMAC(cookie_key, 발급 시각 | 출발지 IP) 의 앞 8바이트. 서버는 `REQ` 에 아무것도 기억하지 않는다. `AUTH` 를 받으면 mac 을 다시 만들어 맞는지, 수명(5초) 안인지 본다. 같은 `AUTH` 의 재전송은 기기마다 "마지막으로 받아들인 nonce 의 발급 시각"보다 늦은 것만 받아 막는다. 기기 목록을 다시 읽으면 그 기억이 사라지므로, 다시 읽은 시각(`nonce_floor`) 이전의 nonce 는 받지 않는다.

## 검토한 다른 길

- **기기마다 nonce 를 기억하는 표** (v8 까지) — 위조한 `REQ` 가 표의 상태를 바꾼다.
- **IKEv2 의 `COOKIE` 처럼 부하가 높을 때만 쿠키** — 평소와 부하 때의 두 길이 생긴다. 상태 없는 쿠키가 비싸지 않아 늘 쓴다.
- **WireGuard 처럼 타임스탬프** — 왕복 하나를 줄이지만 클라이언트의 시계에 기댄다.

## 결과

- 출발지를 위조한 `REQ` 는 HMAC 한 번으로 끝나고, 답이 `REQ` 보다 크지 않아 증폭이 없다.
- 실제 주소에서 nonce 를 받은 쪽은 수명 동안 `AUTH` 마다 ECDH 한 번(ID 풀기)을 시킬 수 있다. 2026-10-25 부터 그 ECDH 는 표 잠금 밖에서 해 데이터 경로를 세우지 않는다 (0005). 2026-10-26 부터 `AUTH` 는 주소마다 초당 20개(`-r`)까지 받고, `REQ` 는 표 잠금 없이 답한다.
- nonce 는 출발지 IP 에 묶인다. 핸드셰이크 도중 주소가 바뀌면 처음부터 다시 한다.
