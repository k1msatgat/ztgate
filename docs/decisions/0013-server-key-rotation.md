# 0013. 서버 키는 연결된 세션 안에서 기기마다 새 키로 옮기며 바꾼다

- 상태: 제안 (구현 전. 아래 "정할 것" 이 정해지면 채택)
- 날짜: 2026-10-27

## 맥락

공개키 기기(`p256:`, v8)의 기기 키는 `ECDH(서버 고정 키, 기기 고정 키)` 에서 뽑는다 (ADR 0004). 그래서 서버 키(`/etc/ztgate/server.key`)를 바꾸면 모든 기기의 키가 함께 바뀌고, 기기들은 새 등록 코드로 다시 등록해야 한다. 기기가 수백 대면 서버 키는 사실상 바꿀 수 없다. 상용화 검토에서 막는 것(BLOCKER)이었다 — 키의 나이를 제한하는 고객 정책, 서버를 옮기거나 운영자가 바뀔 때를 맞출 수 없다.

## 제안

서버는 회전하는 동안 키를 둘 가진다: 지금 키(`server.key`)와 다음 키(`server.key.next`). 기기는 지금 키로 연 세션 안에서 새 고정 키 쌍을 만들어 그 공개키를 올리고(새 메시지 `ROTATE`, 세션 패킷), 운영자가 끝내면 모두 다음 키로 넘어간다.

1. **시작** (`ztgate_ctl serverkey_rotate_begin`). 다음 키를 만든다. 진행 중인 회전이 있으면 거절한다.
2. **상태를 keepalive 마다 보낸다.** 서버는 keepalive 답에 `다음 서버 공개키 | 그 기기에 대해 기록한 새 공개키의 해시` 를 함께 싣는다. 기기는 새 키 쌍을 먼저 저장한 뒤(다음 신원) 그 공개키를 보내고, 서버가 돌려주는 해시가 자기 것과 같아질 때까지 keepalive 마다 다시 보낸다. 답(3번째 메시지)이 따로 없으니 잃어버리거나 순서가 바뀌어도 수렴한다 (net_config 의 "늘 전부 다시 보낸다" 와 같다).
3. **서버의 기록은 기기 목록이 아니라 따로 둔 파일** `devices.next` 다: 첫 줄에 다음 키의 지문, 그다음 `id 공개키` 줄들. 서버가 잠금 아래에서 덧붙이고 메모리의 행만 고친다 — 기기 목록을 다시 읽지 않는다 (다시 읽으면 쓰기 잠금 아래에서 파일 전체를 읽고, nonce 바닥을 올려 진행 중인 핸드셰이크가 모두 무효가 된다). 쓰기 전에 그 공개키가 P-256 위의 점인지 다음 키와의 ECDH 로 확인한다. 회전 중이 아니거나 공유 키 기기면 받지 않는다. 관리 도구는 이 파일을 건드리지 않고, `devices.conf` 의 형식도 그대로다.
4. **끝** (`serverkey_rotate_finish`). 서버를 멈추고, `server.key` 를 `.old` 로 링크한 뒤 `.next` 를 `server.key` 로 rename 하고(되돌릴 수 없는 한 점이 이것 하나), 띄운다. 서버는 뜰 때 `devices.next` 의 지문이 지금 키와 같으면 그 공개키들을 덮어 쓴다. 기기 목록에 합치는 것은 그 뒤에 해도 된다. 끝내기는 몇 번 불러도 같은 결과다.
5. **넘어가기.** 기기는 `CHALLENGE` 의 서버 공개키가 지금 고정한 키면 지금 신원으로, 다음 키면 다음 신원으로 답한다. 고른 신원은 그 핸드셰이크 안에만 두고(`cfg` 를 바꾸지 않는다 — 다음 공개키는 모든 기기가 알아서 누구나 그것으로 CHALLENGE 를 위조할 수 있다), `RES_HANDSHAKE` 의 tag 가 맞은 뒤에만 다음 신원을 지금 신원으로 올린다.

## 정할 것

- **커넥터.** 커넥터는 Linux 클라이언트(`vpn_client connector`)로만 돈다. Linux 클라이언트가 `ROTATE` 를 모르면 끝내는 순간 모든 커넥터가 끊기고, 내부망으로 가는 길이 모두 사라진다. Linux 클라이언트에 회전을 넣거나, 끝내기가 옮기지 않은 커넥터가 있으면 거절해야 한다. 앞의 것은 Linux 클라이언트를 고도화하는 일이라 사용자가 정한다.
- **예전 키의 유예.** 끝낸 뒤 꺼져 있던 기기는 다시 등록해야 한다. REQ 에 고정한 키의 지문을 실으면 서버가 예전 키를 정한 기간 더 받아 그 기기들도 나중에 옮기게 할 수 있지만, 예전 키가 그만큼 오래 산다.

## 검토한 다른 길

- **기기 키를 서버 키와 떼기 (서버가 기기 키를 따로 저장)** — 기기 목록에 비밀(대칭 키)이 다시 생긴다. v8 이 공개키만 남기게 한 이유를 되돌린다.
- **같은 기기 고정 키로 다음 기기 키를 뽑기** — 소프트웨어 키로 등록한 Windows 기기는 고정 비밀키를 버린다 (DPAPI 에 남는 것은 결과뿐). 새 키 쌍이면 TPM 과 소프트웨어 키가 같은 길로 간다.
- **회전 상태를 `devices.conf` 의 `next=` 로 두기 (첫 안)** — 적대적 검토가 막았다. 관리 도구와 예전 서버는 모르는 낱말이 있는 기기 목록을 통째로 거부하고, 잘못된 공개키 하나가 서버의 기기 목록 전체를 못 읽게 만들 수 있으며, ROTATE 마다 기기 목록을 다시 읽으면 몰려든 회전이 서버를 멈춘다. 끝내는 도중에 죽으면 새 공개키와 예전 서버 키가 섞인다.
- **세 메시지(제안, 요청, 결과)** — 결과를 잃거나 기기가 그 사이에 다시 뜨면 서버는 기록했는데 기기는 모르는 상태가 남는다. 상태를 keepalive 마다 보내면 그런 상태가 없다.

## 결과 (채택하면)

- 서버 키를 기기 재등록 없이 바꿀 수 있다. 끝낼 때 모든 세션이 한 번 다시 핸드셰이크한다.
- **유출 뒤의 대응은 아니다.** 지금 서버 키를 가진 쪽은 기기 키를 뽑아 그 기기인 척 다음 신원을 올릴 수 있다. 같은 기기에서 서로 다른 공개키가 오면 충돌로 표시하고 옮기지 않으며 감사 로그에 크게 남긴다. 서버 키가 샜으면 새 서버 키 + 모든 기기의 재등록이다. 회전은 정기 교체용이다.
- 다음 신원으로 올리다 죽어도 TPM 키를 잃지 않게, 지금 신원이 쓰는 TPM 키 이름은 절대 지우지 않는다.
- `server.key.old` 는 유예 기간 뒤 지운다. 남아 있는 동안 그것을 가진 쪽은 아직 다시 붙지 않은 기기에게 서버인 척할 수 있다.
