# 0008. 설정은 텍스트 파일이고, 고치는 길은 ztgate_ctl 하나다

- 상태: 채택
- 날짜: 2026-10-16 (이름을 ztgate 로 바꾸며 관리 도구를 `ztgate_ctl` 로 정리, `5143e4a`)

## 맥락

기기 목록, ACL, 등록 대기 목록을 사람이 손으로, MCP 도구로, 웹 콘솔로 고친다. 서버도 등록 코드로 기기가 올라오면 기기 목록에 한 줄을 더한다. 고치는 쪽이 여럿이면 검증과 잠금이 여러 곳에 흩어진다.

## 결정

- 설정은 텍스트 파일(`devices.conf`, `acl.conf`, `enroll.conf`)이다. 서버는 `SIGHUP` 으로 임시 표에 읽어 검사가 끝난 뒤에만 바꿔 끼우고, 깨진 파일이면 이전 것을 그대로 쓴다.
- 파일을 고치는 프로그램은 관리 헬퍼 `ztgate_ctl`(JSON 명령을 받는 `mcp/ctl.cjs`) 하나다. MCP 서버와 웹 콘솔은 그것을 부를 뿐 직접 고치지 않는다. 검증(이름 글자, 개수 상한, 주소 겹침), 잠금(`.ztgate.lock`, flock — 서버와 같은 잠금), 서버 다시 읽기가 한 곳에 있다.

## 검토한 다른 길

- **데이터베이스 (SQLite 등)** — 동시 쓰기와 질의가 쉽지만, 서버가 DB 를 읽게 되고 사람이 파일을 보고 고치는 운영이 사라진다.
- **서버에 관리 API** — 서버가 인증된 관리 요청을 받는 공격면이 생긴다. 지금 서버의 상태 소켓은 읽기 전용이다.

## 결과

- 파일을 보면 지금의 정책이 보이고, `git` 으로 관리할 수도 있다. 서버는 관리 요청을 받지 않는다.
- 손으로 고칠 때는 잠금을 잡지 않으므로, 등록과 겹치면 한쪽이 고친 것이 사라질 수 있다 (`flock` 으로 잡고 고친다 — README "운영").
- 서버 여러 대의 설정을 맞추는 것은 운영자의 몫이다.
