# 0006. IPv4 와 IPv6 를 소켓 하나(듀얼스택)로 받는다

- 상태: 채택
- 날짜: 2026-10-24 (`51f4abd`)

## 맥락

IPv6 망에 있는 클라이언트도 서버에 붙어야 한다 (터널 안은 IPv4 그대로). 서버는 끝점(클라이언트의 바깥 주소)을 세션, nonce, 로그, 상태, 감사 로그에 쓰고, 요청이 도착한 주소에서 답해야 한다 (`IP_PKTINFO`, 주소가 여럿인 서버).

## 결정

- UDP 와 TCP 모두 `AF_INET6` 소켓 하나에 `IPV6_V6ONLY 0` 으로 받는다. IPv4 는 `::ffff:a.b.c.d` 로 온다.
- 서버의 끝점은 늘 `sockaddr_in6` 하나(`net_ep_t`)다. nonce 의 mac 은 그 16바이트 주소를 덮는다.
- 도착 주소는 `IPV6_PKTINFO` 로 받아, 끝점의 `sin6_scope_id` 자리에 도착 주소 표의 번호를 둔다. TCP 끝점은 `sin6_family = AF_UNSPEC` 으로 표시하고 `flowinfo` 에 연결의 세대를 둔다.
- 로그와 상태는 IPv4 끝점은 전처럼 `a.b.c.d:port`, IPv6 는 `[주소]:port`.

## 검토한 다른 길

- **소켓 둘(IPv4, IPv6)** — 커널 설정과 상관없이 확실하지만, epoll 에 거는 것, 워커마다의 소켓(0005), 보낼 때 고르는 것이 모두 두 벌이 된다.
- **끝점을 `sockaddr_storage` 로** — 주소 길이와 종류를 늘 따로 따져야 한다.

## 결과

- 코드 경로가 하나라 IPv4 와 IPv6 가 같은 시험을 지난다 (auth_check, e2e).
- `sin6_scope_id` 를 다른 뜻으로 쓰므로 **링크 로컬 주소(fe80::)로는 붙지 못한다** — 답할 인터페이스를 고르지 못한다. 전역 주소나 ULA 를 쓴다 (README "알려진 제약").
- `net.ipv6.bindv6only=1` 인 장비에서도 소켓 옵션이 우선한다.
